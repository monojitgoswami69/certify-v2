# Certify pre-launch audit

Reviewed commit `7ac9415` on 25 November 2026. The review covered sign-in, permissions, Gmail, Studio, registration, exports, public verification, private data, database provisioning and recovery, CI, hosting limits, and operational behavior. The findings below distinguish behavior observed in a disposable local environment from production conditions that still need confirmation.

## Release blockers

### Payload sizes can break issuance, downloads, and mailing on Vercel

A synthetic 4,000 × 3,000 PNG measured 4,960,381 bytes on disk. Certify accepted it locally, but the registration request measured 6,614,306 bytes and the public render response measured 6,614,270 bytes. Both exceed the 4.5 MB Vercel Functions default. Studio currently accepts templates up to 15 MB and the mail route accepts up to 24 MiB of attachments. Vercel has an opt-in 20 MiB inbound beta for eligible configurations. The public render response still needs its own solution. [Vercel Functions limits](https://vercel.com/docs/functions/limitations) · [Vercel inbound payload beta](https://vercel.com/changelog/vercel-functions-now-support-request-bodies-up-to-20mib) · [Studio template upload](src/components/sidebar/TemplateUpload.tsx#L77) · [Public render response](src/app/api/verify/%5Bid%5D/asset/route.ts#L66) · [Mail request limits](src/app/api/send-email-v2/route.ts#L46)

- Immediate release fix. Use a deployment-aware byte budget and report oversize inputs before saving, issuing, or sending. Split large CSV uploads by serialized bytes and retain per-row retry state. Check that every accepted issued design can subsequently be retrieved under the response budget.
- Durable fix. Move immutable artwork to object storage. Keep the layout, frozen recipient fields, and a versioned asset reference in the database. Preserve certificate IDs and make each archived asset available only through its authorized or public-verification path. Keep generated certificate files reproducible from the design as planned.

### The standard database migration command does not provision the app

I applied the journal to a fresh PostgreSQL fixture. The result lacked the account allowlist, issuance permission, and frozen issue design. Applying the six subsequent SQL files produced the required schema. The custom stamp script records the journal entries as applied and currently assumes the target already contains the corresponding schema. A fresh Vercel environment or restore can appear to deploy successfully with an incomplete database. [Migration journal](drizzle/meta/_journal.json) · [Baseline stamp script](scripts/db-stamp-baseline.mjs) · [CI workflow](.github/workflows/ci.yml)

- Consolidate migrations into one supported command. Reconcile the existing production history before adding entries and ensure the stamp tool can only mark migrations verified to exist.
- In CI, create a disposable PostgreSQL database, run the same migration command used for deploys, boot the production build, and run the smoke suite. Exercise an upgrade from the legacy schema and a restore separately.

## High-priority findings

| Area | Finding and impact | Recommended fix |
| --- | --- | --- |
| Issuer history | A normal profile edit changed the **Issued By** label on an existing certificate link in the test. Verification reads the current account name. Rendered certificate layout and fields already have their own issued snapshots. [Verification query](src/app/api/verify/%5Bid%5D/route.ts#L70) · [Profile settings](src/app/api/user/profile/route.ts#L22) | Freeze the issuer name at issuance. Backfill only when the original issuer name can be supported. Keep existing certificate IDs and links. |
| Template versions and draft recovery | Restoring an older template revision placed the old layout over newer artwork with a different hash. The UI describes a layout restore but gives no compatibility check. Draft recovery also matches by filename or event name and image dimensions. Distinct images with the same name and size can be treated as the original. [Version restore](src/app/api/templates/%5Bid%5D/versions/route.ts#L103) · [Draft artwork matching](src/app/editor/EditorClient.tsx#L198) | Refuse a layout restore when the artwork hash differs or restore the complete matching revision. Have drafts record a stable asset ID and content hash. Keep a manual fallback for older drafts. |
| Protection across instances | The Gmail sender quota uses a PostgreSQL row lock and passed concurrent checks. Login, issuance, upload, and verification throttles use process-local counters. Their documented budgets do not aggregate across Vercel instances. [Mail quota](src/lib/mail-quota.ts#L6) · [Process-local limiter](src/lib/rate-limit.ts#L15) | Put public verification and authentication abuse controls at the edge or in a shared store. Keep the server-side mailbox quota and verify production client-IP handling. |
| Large or damaged images | File size and signatures are checked in several paths, but native pixel area and complete layout geometry lack a common budget. A small compressed file can still require a large decoded canvas. The preview allocation cap protects the interactive buffer and full-resolution export and public rendering still need safe bounds. [Issued design validation](src/lib/event-design-validation.ts#L4) · [Preview allocation](src/components/canvas/canvas-geometry.ts#L1) · [Public renderer](src/components/verify/CertificatePreview.tsx#L102) | Validate actual PNG/JPEG/WebP dimensions, total decoded pixels, and finite in-bounds geometry on new writes. Handle unsupported legacy artwork without taking down existing verification links. |
| Record retention and ownership | Drafts and issued records can retain roster columns that recipients never see. Account deletion cascades through issued events and certificates, so it could invalidate every link from that issuer. Backups store records as local JSON and exclude Gmail credentials by design. The repository has no documented retention and deletion procedure tying these behaviors together. [Privacy policy](src/app/privacy/page.tsx#L91) · [Database ownership](src/db/schema.ts#L44) · [Backup script](scripts/backup-db.mjs#L13) | Keep only the necessary private roster fields, document a deletion workflow that accounts for existing verification links, and define retention for protected off-site backups. Include the need for Gmail reauthorization in the recovery runbook. |
| Sessions and outages | Both sign-in endpoints return session tokens to JavaScript alongside the HttpOnly cookie. The browser store still requires the response token even though its main session uses the cookie. Several protected handlers call database-backed auth before their error handler, so a database outage can bypass the normal JSON error path. [Login response](src/app/api/auth/login/route.ts#L74) · [Client session](src/store/useAuthStore.ts#L113) · [Auth verification route](src/app/api/auth/verify/route.ts#L5) | Make new browser sessions cookie-only once old client compatibility is retired. Normalize dependency failures to a recoverable 503 with safe, correlated logging. |

## Capacity and delivery trade-offs

- The detailed dashboard loads the whole event roster in one response. The CSV path can also include the full stored row data. The admin accounts query computes multiple certificate aggregates per account. Use cursor pagination for private lists and a bounded export path before relying on the app for large rosters. [Issuer dashboard query](src/app/api/dashboard/route.ts#L74) · [Admin account query](src/app/api/admin/accounts/route.ts#L29)
- An issued design freezes coordinates and recipient fields. Font binaries and renderer behavior can change as the app and fonts evolve. Version the renderer and pin the font assets if customers need stable reproduction over time. This can be done while generating files on demand. [Issued certificate renderer](src/lib/issued-certificate.ts#L4) · [Issued design shape](src/lib/event-design.ts#L13)
- Browser-controlled delivery is an accepted constraint. Closing the tab interrupts the queue, and timeouts may leave an uncertain send outcome. Durable delivery records can make reconciliation safer while keeping the browser in control of dispatch. [Mail batch state](src/components/email/useEmailBatchRunner.ts#L69) · [Gmail response handling](src/app/api/send-email-v2/route.ts#L206)

## What passed

- Lint, 68 unit tests, and 118 API smoke checks passed locally on the audited commit. The npm production dependency audit reported zero known advisories at the time of the check.
- The previous browser verification of this same commit covered 48 issued certificates, 144 exported files, native resolution, transparent PNG output, QR decoding, public verification, and simulated Gmail delivery. The browser fallback and access segregation were also exercised. The audit repeated ordinary issuance, template, and verification operations against synthetic data.
- The current migration sequence was exercised on a disposable PostgreSQL fixture. GitHub CI status and Vercel settings were unavailable to this review. Release sign-off still needs live OAuth and inbox checks, a deployed large-file check, staging recovery, and device and browser coverage beyond the local Chrome pass.

The highest-priority launch work is fixing the payload contract and making database provisioning repeatable. Both affect normal user workflows or release recovery, even when the local feature tests pass.
